## Scope and fixes

Synthetic fixtures only; no protocol arithmetic or contract changes. Settlement retains `MOCK_SETTLEMENT_ONLY`; resale retains `MOCK_GATE_ONLY`; credit retains `MOCK_CREDIT_F04_ONLY`. Executed-funds/finality flags stay false. ORIGINAL_32 labels remain 설계중/미착수. Protocol truth stays in kix-protocol. No dependencies, pins, gate SHA, budgets, production config, or protected paths change.

The new DOM regressions first failed on all three desks: two activations before a React render each dispatched a command, and an old case read could overwrite the newly selected case. Minimal fixes add a synchronous in-flight ref, release it in `finally`, and use selection generations to ignore stale reads, errors, and completion/pending updates. Switching/closing the box-office case clears its display. Credit/resale counters still advance on rejection and reconcile for the originating event; an old rejection does not change the newly selected event's attempt or error. A counter records neither an intent nor recovery authority. Counter values are read from the existing attempt store at dispatch rather than mirrored in React state. The selection generation and synchronous dispatch guard share an internal ref; read success/unknown-case paths share the same guarded view update. These reductions retain the existing byte thresholds without changing budgets.

Mock command receipts are historical snapshots: same-key replay has `duplicate: true`, `applied: null`, and does not move current state. A stored rejection stays rejected after prerequisites change; only a new explicit eligible local action with a fresh key can proceed. This is in-process replay, never HTTP retry. Reusing a resale hold identity after release does not create a second hold.
